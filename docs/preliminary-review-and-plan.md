# FinGuard 代码检查与初赛实施计划

> 实施状态更新：本文前半部分记录的是 2026 年 10 月 12 日实施前检查。当前前端已替换为 React，分阶段核验接口、一键启动与预置演示流程已经实现；以 README 的启动说明为准。

检查日期：2026 年 10 月 12 日。初赛截止：10 月 18 日。方向已确认沿用上市公司财报分析。以下按负责人加 3 名队员、共 4 人安排，10 月 17 日完成验收，18 日只做提交。

## 当前结论

仓库已有 FastAPI 后端和 Streamlit 本地网页原型，适合继续开发。当前最主要的问题是抽取和计算的可信度，以及网页缺少人工核验与原文证据查看。初赛应完成一个范围明确、可重复演示的财报分析流程。建议以同一非金融行业中的 1 家主案例公司和 1 家备用公司为范围，各准备连续两年年报，每次只分析一家公司的可比年度数据。先对候选报告试抽取，再确定演示公司。

初赛演示流程为上传报告、核对抽取数据、执行计算、查看异常及依据、导出报告。季度拆分、完整三表勾稽、复杂业绩归因、监管规则检索、MCP 和多行业覆盖留到后续。

## 检查范围与验证结果

- 阅读 README、docs 下的说明、前后端代码、启动和 CI 配置，以及根目录 7 份 Word 材料的正文。Word 阅读用于了解需求，未做版式检查。
- 运行现有测试，结果为 2 passed；运行 pip check，未发现依赖冲突。
- 用合成文本检查抽取和计算边界，复现了符号丢失、单位上下文遗漏、跨公司比较、同期间重复比较和跨长度期间比较。
- 在临时数据目录中使用 FastAPI TestClient 检查健康接口、PDF 上传、分析、HTML 和 JSON 读取，均返回 200。但空白 PDF 产生 0 条事实、0 条信号时仍被标记为 completed，核验问题列表为空。
- 上述接口检查不等于真实财报准确性验证，也不是浏览器端到端验收。当前 data 中没有真实财报或人工标准答案，GPT 调用未测试。
- 临时接口检查结束时 SQLite 文件仍被占用，清理报错；ledger 使用连接上下文提交事务后没有显式关闭连接，应补齐连接释放。

## 代码结构

| 位置 | 职责 | 目前状态 |
|---|---|---|
| frontend/app.py | 本地网页，上传、选择报告、请求分析、展示与下载 | 已有单页雏形，缺少核验和原文查看 |
| backend/app/main.py | FastAPI 接口入口 | 上传、报告列表、分析及产物读取已接通 |
| backend/app/models/contracts.py | 报告、事实、计算、信号、运行记录的数据结构 | 有基础字段，缺少原始单位、期间性质、复核记录等 |
| backend/app/services/analysis.py | 串联一次分析并保存产物 | 主流程可执行，但没有计算前的质量门槛 |
| backend/app/services/report_store.py | 保存报告登记信息 | JSON 文件存储 |
| backend/app/services/ledger.py | 保存运行与财务事实 | SQLite，尚无人工复核或查询界面 |
| backend/app/tools/ | PDF 文本解析、正则取数、公式、规则、日志 | 核心确定性处理模块 |
| backend/app/agents/ | 固定计划、摘要、简易反证和引用检查 | 多数是普通确定性函数，GPT 只参与可选摘要 |
| data/ | 原始文件、登记信息、评测数据 | 目前主要为空目录占位 |
| runs/ | 每次分析的 JSON、HTML、日志和数据库 | 用于结果追溯 |
| scripts/、docker-compose.yml、.github/ | 安装、容器与测试流程 | 有雏形，需验证演示启动方式 |

实际主链为网页请求 API，API 调用 analysis，解析 PDF 后抽取事实，计算指标并触发规则，最终保存结果并返回网页。SQLite 是本次运行结果的持久化存储，目前尚未构成可先复核、再计算的账本工作流。

## 优先修复的问题

### P0 结果正确性与演示必需项

1. **负数抽取错误**。fact_extractor.py 第 43 行的数字前匹配会吞掉负号或左括号。实测“营业收入 -123.00”和“营业收入 (123.00)”均得到正数 123。先修复符号，再增加对应回归测试。
2. **公司和期间没有隔离**。calculator.py 只按科目分组，再比较排序相邻值。实测 A 公司与 B 公司被比较；同一期间重复记录被算出增长率；2024FY 与 2025H1 被算出变化率。初赛先严格限定同公司、同口径、连续年度可比数据，拒绝混选、重复或不可比输入。
3. **单位、列和口径识别不足**。抽取只取标签后首个数字，单位只看局部文本，没有识别当期列、上年列或合并表。将单位放在远离指标的表头时，123 万元被当作 123 元。至少保留原始值和单位、表头、期间、口径及候选来源，歧义交由人工核对。
4. **抽取结果未经核验就进入计算**。FinancialFact 默认状态为 extracted，主流程仍直接计算并允许生成“已验证”摘要。应拆成抽取、确认、分析三个步骤；确认操作保存修改前后值和来源，不得静默覆盖原始证据。
5. **没有数据也显示完成**。空白 PDF 的实测证明缺失不会阻止成功状态。扫描件或抽取失败应明确提示“不支持或待核验”；缺少某个指标时，对应规则应显示“无法判断”，不能归入“未触发风险”。
6. **证据无法在网页中便捷核对**。已有页码和摘录数据，但页面只展示部分字段，也没有原始 PDF 读取接口。初赛需要通过后端提供 PDF，并从指标或信号打开对应页、原文和计算输入。

### P1 初赛前稳定性与说明修正

- frontend/app.py 第 82 行下载内容复用了局部 response；已有分析结果后再上传文件可能将上传响应作为完整结果下载。应始终从当前 result 或对应 run_id 生成下载内容。
- 上传与运行分析的网络请求缺少完整异常处理，补超时、失败和重试提示。
- HTML 输出直接拼接文件名、期间和模型文本，应进行转义。补入公式、比较期、证据摘录和核验状态，保证导出内容与页面一致。
- Planner 列有 normalize_accounting_basis 和 check_three_statements，主流程没有执行对应模块。界面、README 和计划书必须分清已完成与后续工作。
- verifier 仅检查部分引用存在性，不验证数字正确、口径可比或摘要结论有证据；earnings_driver 是指标列表，尚非利润贡献分解树；counter_evidence 是通用规则补充，尚未主动检索反证。
- run.model 写死模型名，应记录实际配置；本地网页运行不等于模型离线运行，启用远端摘要仍需网络。演示必须能关闭模型，输出确定性模板摘要。
- Docker 中 dashboard 默认访问自身 127.0.0.1，需配置 FINGUARD_API_URL=http://api:8000。初赛优先验证 Windows 本地启动，容器作为后续选项。
- README 安装后直接使用 uvicorn，但 setup.ps1 没有激活环境。改用虚拟环境可执行文件或提供统一启动脚本。
- 当前 Git 分支尚无提交，源码均未跟踪，无法记录有效版本。完成敏感文件与产物排除检查后建立首个提交，再按模块分支协作。

## 初赛网站范围

继续使用 Streamlit、FastAPI、SQLite。已有环境无需为界面重写前后端。网页使用标签页或分区即可，不必实现复杂路由。

| 页面或分区 | 必需内容 | 验收方式 |
|---|---|---|
| 报告管理 | 上传、示例选择、公司与年度、解析状态 | 不同公司和不可比期间不能共同运行 |
| 数据核验 | 六项核心指标、原值、单位、标准化值、来源、确认操作 | 人工更正后能重算，并保留修改记录 |
| 分析总览 | 两年对比、三个已有比率、四类已有信号 | 与人工标准答案一致，缺失单独提示 |
| 证据与导出 | 公式、输入值、PDF 页码与原文、HTML/JSON | 能从一个信号追到每个输入和原文 |

六项指标继续使用营业收入、归母净利润、扣非净利润、经营现金流、应收账款和存货。四类已有信号是利润与现金流背离、应收增长快于收入、存货增长快于收入及非经常性损益贡献较高。阈值应标为项目规则，不能包装成监管认定标准；由负责财务规则的成员解释适用条件。

## 初赛验收清单

- 在目标 Windows 电脑按说明启动，浏览器打开 localhost:8501，后端健康检查正常。
- 选定真实样本的关键数值、期间、单位、口径、页码与人工标准答案一致。人工修订记录可见。
- 同公司可比年度计算与人工答案一致；负数、零分母、重复数据、跨公司、跨期间和缺失值有明确行为。
- 异常信号包含输入值、公式或阈值、证据及待核查事项。
- 数据不足与未触发信号分开显示，原始文件无文本时不伪装成功。
- HTML、JSON 与当前页面结果一致，PDF 能定位到引用页。
- 不启用模型时核心功能可用；启用失败时有提示，并可继续导出确定性结果。
- 相同输入重复三次，事实、计算、规则结果一致。运行 ID 与时间不同属于正常现象。
- 记录样本数量、自动抽取准确率和人工修正后正确率，二者分开报告。
- 用例、版本、运行说明、数据来源、计划书和演示视频均与提交版本对应。

## 初赛之后

第一阶段扩充真实样本和回归集，完善原始值、币种、合并范围、期间性质、重述与复核记录；支持同类半年报比较，再做累计值转单季值和环比。

第二阶段实现真正的会计口径检查与三表勾稽，增加表格位置、页内高亮、语义检索和公司披露解释，逐项验证结论与证据的支持关系。

第三阶段扩展利润驱动分解、针对性反证、规则出处与案例回测。根据评测结果决定是否需要更复杂的智能体编排、独立前端和 MCP 封装。

## 当前原型的启动命令

在项目根目录分别打开两个 PowerShell 终端，使用已有虚拟环境启动。

```powershell
.\scripts\start.ps1
```

浏览器打开 http://127.0.0.1:8000。内置案例使用合成数据并有显著标识，正式演示仍需替换为团队核验过的真实上市公司案例。
