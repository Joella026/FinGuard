# FinGuard 架构

```text
股票代码 → 巨潮公告检索 → 选择完整年报 → 本地 PDF → 解析页文本 → 人工核验批次 → 财务事实账本 → 确定性计算 → 异常规则
                                               ↓
                                         证据与审计日志
                                               ↓
                       GPT 审慎叙述（可选，仅使用已验证结果） → API / 驾驶舱 / HTML 报告
```

## 职责边界

- `tools/`：无模型依赖的确定性能力，负责解析、取数、计算、规则和日志。
- `agents/`：只能编排工具或把已验证的结构化结果转换为自然语言；不得自行计算或虚构证据。
- `services/`：将工具组织成一次可审计运行。
- `models/`：跨模块唯一的数据合同。
- `frontend/`：React 本地网站，只调用后端 API，不直接处理 PDF 或调用模型。

## 初赛交互流程

1. 在顶部切换股票查询或手动上传。股票查询仅面向巨潮资讯的 A 股公告；手动上传不要求股票代码，可登记其他报告主体并指定币种。两年对比要求同一主体、同一币种的连续完整年报。
2. 后端生成包含十二项候选事实的核验批次。
3. 用户逐项确认、修改或标记暂缺；修改保留原因和历史值。
4. 只有完成核验的批次才能运行计算。暂缺事实不进入计算，依赖该事实的规则显示“无法判断”。
5. 结果页以“概览、分析过程、异常信号、原文证据”分层展示；后端统一生成每条规则的数值、阈值、差额和审慎解释，并回链到公式、输入事实、页码和原文。旧运行结果读取时补齐展示说明，不修改原始审计文件。

## 后续 MCP 迁移

网站后端直接调用披露源的 HTTP 查询接口，不需要用 MCP 作为网站与巨潮之间的传输层。若以后要让外部智能体调用网站检索能力，再将搜索、导入、核验等已有服务封装为 MCP 工具。巨潮网页端点不是正式签约的数据 API，生产使用前应评估授权接口或金融终端合同。
